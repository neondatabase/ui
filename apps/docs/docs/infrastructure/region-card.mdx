`RegionCard` is the server-info chip that floats over region visualizations: an uppercase kicker, the region name, and a mono line with the region id plus a color-coded `ping: x ms` (green under 80 ms, amber under 180, red past that — the same `pingTone` helper the whole region family shares). It ships unpositioned; anchor it with `className` over a [RegionSelect](/infrastructure/region-select) map, a [RegionGlobe](/infrastructure/region-globe), or the [CreateProject](/blocks/create-project) block — all three use this exact component.

<RegionCardPreview />

## Install

```bash
npx shadcn@latest add https://ui.neon.com/r/region-card.json
```

## Usage

```tsx
import { RegionCard } from "@/components/neon-ui/region-card";

<RegionCard
  className="absolute bottom-3 left-3"
  title="AWS Europe Central 1 (Frankfurt)"
  regionId="aws-eu-central-1"
  ping={pings["aws-eu-central-1"]}
/>;
```

## Wiring to Neon

The card is one region's readout, so it takes a single entry off the active-regions list:

```tsx
import { createNeonClient } from "@/lib/neon-client";

const client = createNeonClient(process.env.NEON_API_KEY);
const { data } = await client.getActiveRegions({});
const region = data.regions.find((item) => item.region_id === regionId);

<RegionCard title={region.name} regionId={region.region_id} ping={ping} />;
```

`ping` never comes from the API. It is a browser measurement, so take it from `useRegionPing` (shipped with [RegionGlobe](/infrastructure/region-globe)) and pass `null` until the first round-trip lands.

## Notes

- Exports `pingTone(ping)` — the shared green/amber/red class mapping — for readouts outside the card.
- The entrance fade is `motion-reduce` guarded; pair with an `aria-live="polite"` wrapper when the card announces selection changes.
